❯ How to use librosa?                                                           

● Using librosa

  librosa is a Python library for audio analysis. The basic workflow is to load
  audio into a NumPy array, then compute features from it.

  1. Load audio

  import librosa

  y, sr = librosa.load("cat1.wav", sr=22050, duration=4.0)

  - y is a 1-D float array of the waveform samples.
  - sr is the sample rate in Hz.
  - sr=22050 resamples the audio. Use sr=None to keep the file's original rate.
  - duration=4.0 reads only the first 4 seconds.

  The notebook's load_audio() then pads or truncates y to a fixed length, so
  every file gives the same feature size.

  2. Basic info

  librosa.get_duration(y=y, sr=sr)   # length in seconds
  len(y) / sr                         # same thing

  3. Visualize

  import matplotlib.pyplot as plt
  import librosa.display
  import numpy as np

  # Waveform
  librosa.display.waveshow(y, sr=sr)

  # Mel spectrogram
  S = librosa.feature.melspectrogram(y=y, sr=sr, n_mels=128)
  S_db = librosa.power_to_db(S, ref=np.max)
  librosa.display.specshow(S_db, sr=sr, x_axis="time", y_axis="mel")
  plt.colorbar(format="%+2.0f dB")
  plt.show()

  4. Extract features

  All of these live in librosa.feature. Each returns a 2-D array of shape
  (n_features, n_frames), so the notebook averages over time with np.mean(..., 
  axis=1).

  mfcc      = librosa.feature.mfcc(y=y, sr=sr, n_mfcc=13)   # timbre
  chroma    = librosa.feature.chroma_stft(y=y, sr=sr)       # pitch classes (12)
  contrast  = librosa.feature.spectral_contrast(y=y, sr=sr) # peak vs valley (7)
  tonnetz   = librosa.feature.tonnetz(y=librosa.effects.harmonic(y), sr=sr)  # 6
  centroid  = librosa.feature.spectral_centroid(y=y, sr=sr) # "brightness"
  rolloff   = librosa.feature.spectral_rolloff(y=y, sr=sr)
  bandwidth = librosa.feature.spectral_bandwidth(y=y, sr=sr)
  flatness  = librosa.feature.spectral_flatness(y=y)
  rms       = librosa.feature.rms(y=y)                      # loudness
  zcr       = librosa.feature.zero_crossing_rate(y)         # noisiness

  5. Turn features into a model input

  This is what extract_features_full() does in the notebook:

  feat = np.hstack([
      mfcc.mean(axis=1), mfcc.std(axis=1),
      chroma.mean(axis=1), contrast.mean(axis=1), tonnetz.mean(axis=1),
      centroid.mean(), rolloff.mean(), bandwidth.mean(),
      flatness.mean(), rms.mean(), zcr.mean(),
  ])   # -> 57 numbers per audio file

  Stack one such vector per file into a matrix X, then pass it to scikit-learn
  (StandardScaler, then RandomForestClassifier).

  Tips

  - Always use keywords. Recent librosa versions require y= and sr= as keyword
    arguments, so write librosa.feature.mfcc(y=y, sr=sr).
  - Missing codec errors. If librosa.load fails on non-WAV files like MP3,
    install ffmpeg. WAV works out of the box through soundfile.
  - Playing audio in Jupyter: use IPython.display.Audio(y, rate=sr).
  - Docs: https://librosa.org/doc/latest/

❯ Explain the third cell?                                                       

● The third code cell defines three helper functions: load_audio,
  compute_basic_stats and extract_spectral_features. Defining them produces no
  output. They are used by later cells.

  load_audio(path, sr, max_duration)

  y, sr_out = librosa.load(path, sr=sr, duration=max_duration)
  target_len = int(sr * max_duration)
  if len(y) < target_len:
      y = np.pad(y, (0, target_len - len(y)))
  else:
      y = y[:target_len]
  return y, sr

  - It loads the file, resamples it to 22,050 Hz, and reads at most 4 seconds.
  - It then makes the clip exactly 4 s long: 4.0 × 22050 = 88,200 samples. Short
    clips are padded with silence (zeros) at the end. Longer clips are cut.
  - It returns the waveform y and the sample rate. Fixed length matters because
    every file then gives features of the same shape.
  - The comment mentions soundfile, but the function only uses librosa.load.

  compute_basic_stats(y)

  It returns a dictionary of simple waveform statistics:
  - Mean, standard deviation, max and min amplitude.
  - rms is the root mean square, a measure of loudness.
  - zero_crossing_rate is how often the signal crosses zero. (y[:-1] * y[1:]) < 
    0 is true wherever consecutive samples have opposite signs, and the cell
    divides the count by the length. A high rate suggests a noisier or
    higher-pitched sound.

  extract_spectral_features(y, sr)

  It returns the average over time of four frequency-based measures:
  - Spectral centroid: the "center of mass" of the spectrum, which relates to
    brightness. High means a sharper sound.
  - Spectral rolloff: the frequency below which most of the energy lies.
  - Spectral bandwidth: how spread out the frequencies are.
  - Spectral flatness: how noise-like (near 1) or tonal (near 0) the sound is.

  Each librosa call returns one value per time frame, and .mean() collapses that
  to a single number per file. The values are cast to float so they are plain
  Python numbers.

  How they're used

  Only load_audio is called later, in the waveform plot and in feature
  extraction. compute_basic_stats and extract_spectral_features are never called
  in this notebook. The full feature extractor, extract_features_full,
  recomputes the spectral features itself.

● The fourth code cell is the EDA step for durations and metadata. It checks how
  long the raw recordings are, before any trimming or padding.

  Part 1: Read each file's length and sample rate

  for p in tqdm(df['filepath'], desc="durations"):
      try:
          info = sf.info(p)
          duration = info.frames / info.samplerate
          sr_list.append(info.samplerate)
          duration_list.append(duration)
      except Exception:
          y, sr = librosa.load(p, sr=None, duration=None)
          duration_list.append(librosa.get_duration(y=y, sr=sr))
          sr_list.append(sr)

  - It loops over every file path in df. tqdm shows a progress bar.
  - sf.info(p) reads only the file header, so it's fast. Duration is frames / 
    samplerate.
  - If soundfile can't read a file, the except branch loads the whole file with
    librosa and measures it. This is slower but more tolerant.
  - sr=None keeps the original sample rate instead of resampling.

  Part 2: Store and summarize

  df['duration_raw'] = duration_list
  df['orig_sr'] = sr_list
  print(df['duration_raw'].describe())

  This adds two new columns to df: each file's original length in seconds and
  its original sample rate. describe() prints the count, mean, standard
  deviation, min, quartiles and max of the durations. It helps you judge whether
  the 4-second MAX_DURATION is reasonable.

  Part 3: Two plots

  - Histogram with a KDE curve shows the distribution of durations across all
    files. It is saved as eda_results/duration_hist.png.
  - Boxplot by class compares the cat and dog duration ranges and outliers. It
    is saved as duration_box.png.

  If one class were consistently longer, a model could learn clip length instead
  of sound. That's the reason for the class comparison.

  Code cell 1: extract_features_full(fp)

  The function turns one file into one 57-number vector.

  cut

  Each librosa feature function returns a table with one column per time frame,
  for example (13, ~173) for MFCC. axis=1 collapses time, so every file gives
  the same number of values regardless of its content. This is why load_audio
  fixes the length first.

  - MFCC mean and std: the mean is the typical timbre, and the std is how much
    it changes.
  - Chroma and contrast: chroma_stft gives 12 rows and spectral_contrast gives 7
    rows, each averaged over time.
  - Tonnetz: librosa.effects.harmonic(y) first removes the percussive part and
    keeps the harmonic part, then tonnetz gives 6 values. It is wrapped in
    try/except and falls back to 6 zeros if it fails.
  - Scalar features: centroid, rolloff, bandwidth, flatness, RMS and ZCR each
    become a single average, via .mean() or np.mean().
  - Combine: np.hstack([...]) joins everything into one flat array: 13+13+12+7+6
    plus the 6 scalars = 57 numbers.

● This is the PCA scatter plot from your own run. It looks like the Kaggle plot
  I showed earlier, flipped left to right, and that flip is normal (see below).

  What it shows

  Each dot is one audio clip, 1,050 in total. Each clip has 57 features. PCA
  found the two directions in that 57-dimensional space that capture the most
  variation and used them as the axes.

  - x-axis (PC1): the direction of greatest variance. It is not any single
    feature, but a weighted mix of many.
  - y-axis (PC2): the second-greatest direction, at a right angle to PC1.
  - Colors: blue is cat and orange is dog. The labels were not used to compute
    the plot, only to color it afterward.

  How to read it

  1. The classes partly separate, mostly vertically. Cats (blue) sit higher,
     mostly above y ≈ 0. Dogs (orange) sit lower, mostly below y ≈ 0. So PC2
     carries a lot of the cat/dog difference.
  2. There is a large overlap in the dense cluster around x between -3 and 5, y
     between -3 and 4. Two components can't fully separate the classes. This
     matches the t-SNE plot, which separated them better.
  3. A long tail extends to the left (x < -5). These are unusual clips with
     extreme feature values, probably long or loud recordings or clips with a
     high noise level. They are mostly the same class at the same height: the
     far-left tail splits into blue dots at y > 0 and orange dots at y < 0.
  4. Outliers matter for scaling and trees. Points far from the cluster stretch
     PC1, which is why most of the data is squashed into a narrow band on the
     right.

  Why it's mirrored compared to the earlier plot

  PCA axes have no fixed sign. The mathematical solution is the same if an axis
  is flipped, so different runs or library versions can show the same structure
  mirrored. The meaning is identical. Only the direction of the x-axis differs.

  What it tells you about the model

  The two clouds are visibly different, so the features contain real class
  information. Even a 2D squeeze separates much of it. The overlap shows that a
  single straight line in this view would make mistakes. That is why a model
  using all 57 features, like the Random Forest at 98.6%, does much better than
  this picture suggests.

  Caveats

  - PCA is a lossy summary. The 2D view keeps only part of the variance, and you
    can check how much with pca.explained_variance_ratio_.
  - Overlap in 2D doesn't mean the classes overlap in 57D. Separation can exist
    in dimensions the plot discards.

  1. Go to https://www.kaggle.com and sign in. A free account works. Google

  2. Click Create, then New Notebook. The left sidebar has Create, and the Code
     section lists your notebooks.
  3. The notebook opens with a Python kernel and a first empty code cell.

  Add the dataset

  For this audio project:

  1. Open the dataset page, https://www.kaggle.com/datasets/stealthtechnologies/
     cats-vs-dogs-audio-classification
  2. Click New Notebook on that page. The dataset is attached automatically.

  dataset name, and click +.

  original notebook's DATA_DIR was a /kaggle/input/... path. To see the exact
  structure, run:

  import os

      print(root, len(files))

  Run code

  - Write code in a cell and press Shift+Enter to run it.
  - Use + Code or + Markdown to add cells.
  - The first run can take a minute while the session starts.

  Other settings

  - Install a missing library: !pip install package-name in a cell. Internet
    access must be on (Settings, then Internet toggle). Phone verification may
    be needed to turn it on.
  - GPU or TPU: Settings or the right panel, then Accelerator. Use a GPU only
    for deep learning such as your CNN notebook. The audio Random Forest
    notebook doesn't need it.
  - Save files: write to /kaggle/working/ (this is where eda_results/ goes).

  - Save your work: Save Version (top right) runs the whole notebook and stores
    it. Pressing Ctrl+S also saves a draft.

  editable copy with the data attached. To import your local .ipynb, use File,

  each 3×3 conv shrinks the image by 2 pixels. Most parameters (97%) are in the
  first Dense layer.

  Training setup: adam optimizer, binary_crossentropy loss, 10 epochs, batch
  size 32. The data is 16,000 training images, 4,000 validation images (an 80/20
  split of train) and 5,000 test images.

  Output meaning: the sigmoid gives P(dog). class_mode='binary' assigns labels
  alphabetically, so cats=0 and dogs=1. Above 0.5 is predicted as dog.
